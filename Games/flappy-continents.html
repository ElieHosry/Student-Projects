Flappy Continents (student proposal)

Assessment: 🔶 Fit with adjustments · Category: Games · Assessed: 2026-07-28 · Status: awaiting instructor approval

Proposal (as submitted): A Flappy Bird–style one-touch game where the characters and environments are themed to the 7 continents, with flying (moving) platforms in the sky in addition to static grounded platforms.

Adjustments required for approval:

  • The obstacle system must be a genuine data-driven procedural pattern engine — flying/moving platforms with authored movement patterns (path, speed, phase), gap and spacing curves — not a handful of hard-coded static pipes. This is what makes the real-time C++ loop load-bearing enough for six CS students.
  • The 7 continents must be a data-driven content pipeline (each continent = biome config + parallax layers + hazard/platform set + character skins, loaded from data with hot-reload), not seven hard-coded scenes.
  • Ship a custom pattern & continent-theme editor as the project's tool (M2 G2): author obstacle/platform patterns and continent themes and preview them live, without recompiling.
  • Leaderboards must run through Firebase with server-checkable score integrity — each run reproducible from a seed + input log (the Replay System requirement) so submitted scores are verifiable, not trusted client values.

References:

  • Flappy Bird (official)
  • Jetpack Joyride Classic — Halfbrick (official)
  • Subway Surfers — "World Tour" themed locations (Wikipedia)

How each requirement applies:

Platform fit: Web browser on mobile and/or Native mobile (Pixel 8a/9a) — one-touch tap play is mobile-native; PC is the development/debug vehicle only.
Front end: Parallax continent rendering, character + skin sprites, moving/flying platforms, tap input, score HUD, menus and continent select. Languages: C++, GLSL.
Back end: Fixed-timestep physics, the procedural pattern/spawn engine, scoring & run statistics, continent/theme & pattern data, Firebase leaderboards and unlock persistence. Languages: C++.
Backend scope: Local now, server-ready (T2) — the score-validation service can lift onto the Linux server in T2.
  • Simulation loop: a fixed-timestep loop runs the tap-to-flap physics and ticks the moving/flying-platform pattern spawner every frame — deterministic and load-bearing, not decorative.
  • Data-driven: continents (biome, parallax layers, hazard/platform sets), obstacle/platform movement patterns, character skins and per-continent difficulty curves are all defined as JSON with hot-reload.
  • Custom tool: a pattern & continent-theme editor — place and tune platform patterns, assemble a continent's layers and hazards, preview live.
  • External DB: Firebase leaderboards + unlocked-continent/skin persistence. Auth ⏭️: optional accounts for cross-device leaderboards (T2). Analytics ⏭️: per-continent difficulty/drop-off funnels (T2).
  • 2D: parallax continent backdrops, sprite characters, animated flying platforms, flap/score/crash VFX. 3D: not needed. Networking: none — leaderboards are asynchronous through Firebase, not a custom real-time layer.
  • Replay System: each run is recorded as seed + timestamped input log and re-simulated deterministically — it validates leaderboard scores and powers a share-a-run feature.
